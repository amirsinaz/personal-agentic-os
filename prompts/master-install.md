# Master Install Prompt

این Prompt را در Codex، Claude Code یا Gemini CLI اجرا کنید.

[راهنمای تصویری و نسخه‌ی به‌روز](https://personal-agenting-os.sina-zy.chatgpt.site) · [Repository و مستندات](https://github.com/amirsinaz/personal-agenting-os)

```text
## هدف

Personal Agentic OS را از `https://github.com/amirsinaz/personal-agenting-os` به‌صورت محلی برای من راه‌اندازی کن تا حافظه‌ی پروژه‌ها، وضعیت کار و مصرف ابزارهای LLM فقط با اطلاعات خودم به‌روز شوند.

## مرزها

- ابتدا فقط محیط را بررسی کن و ابزار فعلی، سیستم‌عامل، Git، Node.js و Obsidian را گزارش بده.
- هیچ نام پروژه، محتوای Vault، Prompt، متن گفتگو، مسیر فایل، Token، Cost، Credential یا Secret را به بیرون ارسال نکن.
- فایل‌های `.env`، Credential Store، Keychain، Browser Profile و پوشه‌های تأییدنشده را نخوان.
- Telemetry پیش‌فرض خاموش است. فقط با رضایت صریح من آن را فعال کن.
- Payload مجاز Telemetry فقط شامل شناسه‌ی تصادفی نصب، نسخه، سیستم‌عامل و نوع نصب است.
- قبل از Clone، دانلود، نصب Dependency یا Skill، اجرای Installer، ساخت سرویس دائمی، نوشتن خارج از پوشه‌ی فعلی یا حذف فایل توقف کن و اجازه بگیر.
- فایل موجود را بدون بررسی و تأیید من بازنویسی نکن.

## اجرا

1. ابزار فعلی را به‌عنوان یکی از Codex، Claude Code یا Gemini CLI تشخیص بده. اگر قابل‌تشخیص نیست، فقط همین مورد را از من بپرس.
2. اگر Obsidian نصب نیست، کاربرد آن را به‌عنوان حافظه‌ی محلی کوتاه توضیح بده و فقط `https://obsidian.md/download` را معرفی کن. پیش از نصب اجازه بگیر. گزینه‌ی Dashboard-only را نیز توضیح بده.
3. پس از اجازه، Repository را دریافت کن و README، راهنمای Skills و فایل‌های Privacy را بررسی کن. اگر فایل ضروری در دسترس نیست، توقف کن.
4. این موارد را یکی‌یکی از من بپرس: Vault موجود یا جدید، مسیر Vault، ابزارهای LLM، مسیر داده‌ی هر ابزار، ریشه‌ی پروژه‌ها، Starter یا Full، اشتراک‌های ماهانه، Price Book تأییدشده، Budget کل یا هر پروژه، و رضایت Telemetry.
5. پیش از تغییر، یک بررسی کوتاه نشان بده: فایل‌های قابل‌ساخت، Skillها، Dependencyها و مسیرهای مقصد. سپس تأیید بگیر.
6. Setup Wizard رسمی Repository را اجرا کن. فقط Adapter ابزارهای منتخب را نصب کن: `AGENTS.md` برای Codex، `CLAUDE.md` برای Claude Code و `GEMINI.md` برای Gemini CLI.
7. اگر Vault جدید است، فقط ساختار عمومی و Templateهای خالی بساز. اگر Vault موجود است، Backup Plan ارائه کن و چیزی را بدون اجازه بازنویسی نکن.
8. اولین Sync را اجرا کن. Dashboard باید فقط داده‌های سیستم من را نشان دهد. در نبود شواهد، `Empty` یا `Unavailable` نمایش بده و داده‌ی نمایشی نساز.
9. یک پروژه‌ی آزمایشی محلی فقط با اجازه‌ی من بساز، وضعیتش را تغییر بده و Sync را دوباره اجرا کن تا به‌روزرسانی Dashboard اثبات شود.
10. اگر پیشنهاد Lean Context وجود دارد، ابتدا فقط Preview را نشان بده. Apply و Rollback هرکدام تأیید جداگانه می‌خواهند. هیچ صرفه‌جویی را بدون مقایسه‌ی کنترل‌شده ادعا نکن.

## پایان کار

فقط وقتی تکمیل را اعلام کن که Dashboard اجرا شود، Sync تغییر محلی را نشان دهد، تمام تست‌ها پاس شوند و هیچ داده‌ی شخصی در Log یا درخواست شبکه نباشد. در پایان مسیر نصب و Vault، Adapterها، وضعیت Telemetry، نتیجه‌ی Sync، فرمان شروع و توقف Dashboard، فایل‌های تغییرکرده و موارد تأییدنشده را گزارش بده. پس از دو شکست تکراری روی یک خطا توقف کن و از من راهنمایی بخواه.
```
