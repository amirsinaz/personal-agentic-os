# Master Install Prompt

این Prompt را در Codex، Claude Code یا Gemini CLI اجرا کنید.

[راهنمای تصویری و نسخه‌ی به‌روز](https://myagenticstack.com) · [Repository و مستندات](https://github.com/amirsinaz/personal-agentic-os)

```text
## هدف

Personal Agentic OS را از `https://github.com/amirsinaz/personal-agentic-os` به‌صورت محلی برای من راه‌اندازی کن تا حافظه‌ی پروژه‌ها، وضعیت کار و مصرف ابزارهای LLM فقط با اطلاعات خودم به‌روز شوند.

## مرزها

- ابتدا فقط محیط را بررسی کن و ابزار فعلی، سیستم‌عامل، Git، Node.js و Obsidian را گزارش بده.
- هیچ نام پروژه، محتوای Vault، Prompt، متن گفتگو، مسیر فایل، Token، Cost، Credential یا Secret را به بیرون ارسال نکن.
- فایل‌های `.env`، Credential Store، Keychain، Browser Profile و پوشه‌های تأییدنشده را نخوان.
- Telemetry پیش‌فرض خاموش است. فقط با رضایت صریح من آن را فعال کن.
- Payload مجاز Telemetry فقط شامل شناسه‌ی تصادفی نصب، نسخه، سیستم‌عامل و نوع نصب است.
- قبل از Clone، دانلود، نصب Dependency یا Skill، اجرای Installer، ساخت سرویس دائمی، نوشتن خارج از پوشه‌ی فعلی یا حذف فایل توقف کن و اجازه بگیر.
- فایل موجود را بدون بررسی و تأیید من بازنویسی نکن.

## اجرا

1. ابزار فعلی را تشخیص بده، سپس از من بپرس اکنون از کدام ابزارها استفاده می‌کنم و در آینده احتمالاً چه ابزارهایی را اضافه می‌کنم. فقط ابزارهایی را ثبت کن که خودم تأیید می‌کنم. اگر ابزار جزو Adapterهای داخلی نیست، فقط در صورت داشتن Connector Manifest معتبر و Transport پشتیبانی‌شده آن را پیشنهاد بده؛ ثبت Connector به معنی نصب یا فعال‌سازی آن نیست.
2. اگر Obsidian نصب نیست، کاربرد آن را به‌عنوان حافظه‌ی محلی کوتاه توضیح بده و فقط `https://obsidian.md/download` را معرفی کن. پیش از نصب اجازه بگیر. گزینه‌ی Dashboard-only را نیز توضیح بده.
3. پس از اجازه، Repository را دریافت کن و README، راهنمای Skills و فایل‌های Privacy را بررسی کن. اگر فایل ضروری در دسترس نیست، توقف کن.
4. این موارد را یکی‌یکی بپرس: Vault موجود یا جدید، مسیر Vault، مسیر داده‌ی هر ابزار منتخب، پوشه‌های مجاز برای بررسی پروژه‌ها، Starter یا Full، اطلاعات مالی اختیاری، رضایت Telemetry، همگام‌سازی مداوم و بررسی هفتگی نسخه.
5. فقط در مسیرهای تأییدشده، کاندیداهای پروژه را پیدا کن. برای هر کاندیدا ابزار منبع، مسیر محلی، شناسه‌ی Git در صورت وجود و نشانه‌های محتوایی غیرحساس مثل نام فایل‌های کلیدی و عنوان‌های تأییدشده را ثبت کن؛ متن خام گفتگو را منتقل نکن.
6. نسخه‌های یک پروژه را با مسیر یکسان یا شناسه‌ی Git یکسان ادغام کن. اگر این دو شاهد وجود ندارد، ادغام محتوایی فقط با حداقل دو نشانه‌ی محتوایی مشترک و هم‌پوشانی قوی مجاز است. شباهت نام به‌تنهایی کافی نیست.
7. پیش از هر تغییر، نقشه‌ی نهایی پروژه‌ها را نشان بده: پروژه‌های Canonical، ابزارهای متصل، نسخه‌های مشترک، موارد نامطمئن و فایل‌های مقصد. برای اصلاح یا تأیید این نقشه از من سؤال کن.
8. پس از تأیید، Setup Wizard رسمی را اجرا کن و فقط Adapter ابزارهای منتخب را نصب کن. هر اتصال باید مستقل قابل فعال‌کردن، غیرفعال‌کردن و Sync باشد.
9. اگر Vault جدید است، ساختار عمومی را بساز. اگر Vault موجود است، Backup Plan ارائه کن. سپس برای هر پروژه‌ی تأییدشده فقط وضعیت فعلی، تصمیم‌های پذیرفته‌شده، پرسش‌های باز و اقدام بعدی را از منابع مجاز به حافظه منتقل کن؛ هر رکورد باید منبع، زمان، سطح اطمینان و وضعیت تأیید داشته باشد. Transcript، Hidden Reasoning و Secret را وارد نکن و فرضیه را Fact تأییدشده ثبت نکن.
10. اولین Sync را اجرا کن و نتیجه را پروژه‌به‌پروژه نشان بده: ایجادشده، به‌روزشده، بدون تغییر، نامطمئن یا ردشده. مورد نامطمئن بدون تأیید وارد حافظه نشود. برای هر پروژه‌ی تأییدشده یک Context Pack پاک‌سازی‌شده‌ی Markdown و JSON بساز تا ابزار جدید فقط همان حافظه‌ی مجاز را دریافت کند.
11. Dashboard را از State تازه بازسازی کن. تعداد پروژه‌ها، ابزارهای متصل، Context Packها، سلامت حافظه، وضعیت آخرین Sync و داده‌های مصرف باید فقط از اطلاعات واقعی من بیاید؛ داده‌ی ناموجود را `Unavailable` نشان بده و موارد تأییدنشده را به صف بررسی بفرست.
12. فقط با اجازه‌ی صریح من، همگام‌سازی مداوم را متناسب با سیستم‌عامل فعال کن. این Sync باید Incremental باشد، تغییرات هر پروژه را به حافظه‌ی مشترک برساند و Dashboard را به‌روز کند؛ اما هیچ آپدیت نرم‌افزاری یا تغییر حافظه‌ای بدون Preview اعمال نشود.
13. مسیر «افزودن ابزار جدید» را آزمایش کن: ابزار و دسترسی‌اش تأیید شود، پروژه‌های آن با نقشه‌ی Canonical مقایسه شوند، فقط Context پروژه‌های مجاز در اختیارش قرار گیرد و ابزارهای قدیمی نیز از تغییرات بعدی همان پروژه به‌روز بمانند.
14. اگر پیشنهاد Lean Context وجود دارد، ابتدا فقط Preview را نشان بده. Apply و Rollback هرکدام تأیید جداگانه می‌خواهند. بررسی هفتگی نسخه نیز فقط اعلان می‌کند و نسخه را خودکار نصب نمی‌کند.

## پایان کار

فقط وقتی تکمیل را اعلام کن که Dashboard اجرا شود، Sync تغییر محلی را نشان دهد، تمام تست‌ها پاس شوند و هیچ داده‌ی شخصی در Log یا درخواست شبکه نباشد. در پایان مسیر نصب و Vault، Adapterها، وضعیت Telemetry، نتیجه‌ی Sync، فرمان شروع و توقف Dashboard، فایل‌های تغییرکرده و موارد تأییدنشده را گزارش بده. پس از دو شکست تکراری روی یک خطا توقف کن و از من راهنمایی بخواه.
```
